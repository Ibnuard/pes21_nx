# Player height and weight synchronization

`tools/sync_player_physique.py` audits selected teams or the entire playable roster's physical data
against the API snapshot used for its roster, then optionally prepares a detached
database update. It never fetches live data or changes the active runtime.

The October 5 roster importer preserved existing players' complete records. New
players received API height and weight, but existing players could retain older
measurements. Physical synchronization is a separate operation so it cannot
accidentally re-import ratings, skills, faces, commentary or team assignments.

## Data contract

- eFootball BaseId is the identity. The canonical state resolves the native ID;
  a matching numeric donor slot alone is insufficient.
- The baseline CPK must match its loose manifest. Every registered native row
  must match the state's checksum before any write. Selected players must also
  match registered name/alias, country, foot and plausible age progression.
- Use a checksum-verified canonical BaseId profile, or a frozen team base card
  when no standalone profile was collected. A licensed/unlicensed base-card
  alias is accepted only when its exact source-card ID was registered or its
  complete biography fingerprint equals the pinned identity. Special cards,
  conflicting observations and unavailable profiles cannot silently supply values.
- The frozen API collection must be the collection referenced by the identity
  state. Single-team mode requires native membership to match that team's API
  response. All-playable mode instead walks the current native squads in the
  accepted selector catalog, so retained local squads and transfers held by the
  earlier importer stay intact. Overlapping club/national identities are changed
  once; they are never duplicated. Established FL26-to-BaseId promotions retain
  their existing mapping and original asset fingerprint.
- Height is integer centimetres, weight is integer kilograms. Strings, booleans,
  missing fields and values outside the existing converter's bounds are rejected.
  A height correction exceeding 10 cm needs a separate identity audit. Optional
  `--height-reviews` entries bind that decision to the exact old row hash, source
  response hash, asset identity and before/after height. They cannot waive name,
  country, foot or age checks. The six reviewed October 5 corrections are in
  `data/player_physique_height_reviews_20261005.json`.
- Only Player.bin bits 216..223 (height minus 100) and 256..262 (weight minus 30)
  may change. Bit 263, all other fields, record count/order/IDs, and every other
  CPK member remain identical. These are native PES21 fields already used by
  the migration converter, not an additional runtime model-scale multiplier.

The API snapshot provides no shoulder width, limb length or chest measurements.
The tool reports the existing appearance adjustments and preserves them, including
head proportions, skin and realface-related fields. Missing appearance rows keep
the engine's default. It does not derive a body shape from BMI or copy another
player's physique. Native appearance nibble 15 is a default sentinel, not +8.

## Commands

Paths below refer to local inputs supplied or generated by the user, not repository
fixtures. `--runtime-base` can be a complete runtime or its latest accepted update
directory containing dt200 and the complete loose manifest. In particular, use the
accepted skin-corrected database, not a pre-realface roster build.

```powershell
python tools/sync_player_physique.py audit `
  --collection local-inputs/efootballdb-updates/2026-10-05 `
  --profiles local-inputs/efootballdb-updates/2026-10-05-profiles `
  --identity-state local-inputs/current-identities/identity-state.json `
  --runtime-base local-inputs/current-runtime-update `
  --team-id 108 `
  --output local-debug/physique-audit

python tools/sync_player_physique.py apply `
  --collection local-inputs/efootballdb-updates/2026-10-05 `
  --profiles local-inputs/efootballdb-updates/2026-10-05-profiles `
  --identity-state local-inputs/current-identities/identity-state.json `
  --runtime-base local-inputs/current-runtime-update `
  --team-id 108 `
  --output local-debug/physique-candidate
```

Repeat `--team-id` to select more teams. An unavailable or incompatible selected
team aborts the operation rather than producing an incomplete success. Output must
be a new directory below ignored `local-inputs/` or `local-debug/`.

For the whole current playable roster:

```powershell
python tools/sync_player_physique.py apply `
  --collection local-inputs/efootballdb-updates/2026-10-05 `
  --profiles local-inputs/efootballdb-updates/2026-10-05-profiles `
  --identity-state local-inputs/current-identities/identity-state.json `
  --runtime-base local-inputs/current-runtime-update `
  --all-playable --catalog local-inputs/current-selector/catalog.json `
  --height-reviews data/player_physique_height_reviews_20261005.json `
  --output local-debug/playable-physique-candidate
```

All-playable mode reports each unavailable or unverified player as held, with
their native/BaseId and reason, and preserves their row. These entries count
toward scope coverage but never toward successful API synchronization. A corrupt
input checksum, duplicate native owner, changed catalog slot or invalid native
roster still aborts the entire operation. The roster importer's existing canonical
profile reconciliation can verify one corrected biography field while the other
identity evidence agrees; foot and country themselves are never patched here.

Audit writes the proposed before/after report only. Apply writes an updated
`identity-state.json`, report, and (when any values differ) `update/LooseCpk/` with
dt200 and the updated manifest. The archive is checked member by member and the
decoded Player.bin must equal the expected result. A second synchronization must
be a no-op. If all selected metrics already match, no replacement CPK is emitted.

Retain the new identity state with an accepted database: future roster syncs must
use its new native row hashes. Asset ownership and existing asset fingerprints
remain pinned; a measurement correction is recorded separately with its source
fingerprint. Do not replace the state with an old public registry.

The roster/NRO build pairing is unchanged because IDs, squads and every nonphysical
field are unchanged. Installation replaces only dt200 and its manifest (manifest
last), with the game closed. Back up these two files first. Retain the accepted
NRO and all PAKs. Start a fresh exhibition match to reload the database. No save
file migration or per-frame hook is involved.

## Barcelona v21 candidate, October 11, 2026

Local baseline: accepted v16 skin update with roster pairing `e861c583ec78e9ae`,
used alongside the user-accepted v20 roof-shadow NRO. API team snapshot:
`fa638ee2be4db5a6`, fetched October 5. All 29 current native Barcelona players
were identity-checked against that snapshot; the current custom roster is retained.

| Player | Height before → API (cm) | Weight before → API (kg) |
| --- | ---: | ---: |
| Joan García | 191 → 193 | 77 → 85 |
| Alejandro Balde | 175 → 177 | 69 → 76 |
| Gavi | 173 → 174 | 70 → 69 |
| Wojciech Szczęsny | 196 → 195 | 90 → 96 |
| Gerard Martín | 186 → 186 | 76 → 82 |
| Eric García | 180 → 180 | 76 → 77 |

The other 23 players already match. This changes ten bytes across six of 43,074
Player records. All 26 existing Barcelona appearance rows have the same body
adjustments as their own locked EF appearance source; three newer players use
the native default. No oversized/undersized native height outside 173–196 cm
was found before the patch. Thus outdated measurements are confirmed, but they
do not establish the cause of every perceived model-size difference.

The candidate has not been tested on Switch. Validate Joan García/Balde/Gavi in a
fresh match with the same camera and compare normal outfield/keeper proportions.
If a particular player still appears abnormally scaled, record that player and
scene so mesh proportions or saved/runtime overrides can be investigated
separately. A correct database value does not prove a correct rendered model.

## Verification

```powershell
python -m pytest tests/test_sync_player_physique.py `
  tests/test_patch_player_skin.py tests/test_pes21_player_migration.py `
  tests/test_stage_efootballdb_update.py tests/test_sync_efootballdb_rosters.py -q
```

Synthetic tests cover exact bit preservation, adjacent weight flags, identity
reuse, duplicate rows/owners, missing appearances, canonical profile precedence,
source checksums, roster drift, conflicting team observations, units/ranges,
and idempotence with the updated identity state. No proprietary fixtures are
committed. The locally generated report contains input/output hashes and complete
member comparison results; it remains ignored alongside the candidate database.
